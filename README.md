# FireCodeCheckerAgent 🔥

**Інженерний AI-агент та Telegram-бот для автоматизованого нормативного аудиту приміщень за ДБН В.1.1-7:2016 «Пожежна безпека об'єктів будівництва»**

Проєкт реалізує динамічний патерн **ReAct (Reason + Act)** із суворою вхідною та вихідною **Pydantic-валідацією**, перевіркою будівельних норм за відкритими державними ресурсами України, доставкою структурованих звітів у **Telegram** та повним обліком токенів і витрат у базі даних **SQLite**.

---

## 📌 Основні можливості

- **Парсинг природної мови у суворі Pydantic-схеми (`BuildingRoomInput`):** розпізнавання назви приміщення, площі, категорії вибухопожежної небезпеки (`А`, `Б`, `В`, `Г`, `Д` — необов'язковий параметр), кількості людей у приміщенні, висоти стелі, розмірів, кількості та напрямку відчинення дверей, групи горючості оздоблення стін (`Г1`–`Г4`) та фактичної відстані евакуації.
- **ReAct-цикл із самокорекцією пошукових запитів:** при отриманні порожнього результату (`Observation: []`) агент перефразовує пошуковий запит за офіційною термінологією ДБН В.1.1-7:2016.
- **Контроль достовірності джерел (Whitelist):** пошук виконується виключно за білим списком верифікованих ресурсів України:
  - `e-construction.gov.ua` — Єдина державна електронна система у сфері будівництва
  - `online.budstandart.com` — БУДСТАНДАРТ Online
  - `dbn.co.ua` — Державні будівельні норми України
- **Вивід чистого ReAct Trace у консоль:** під час обробки запитів з Telegram або CLI у консоль сервера в реальному часі виводиться виключно ланцюжок міркувань агента (`Thought` -> `Validation` -> `Action` -> `Observation` -> `Final Answer`).
- **Аудит та облік витрат у SQLite (`building_project.db`):** кожна перевірка логується у таблицю `inspection_logs` разом із кількістю токенів (`tokens_prompt`, `tokens_completion`, `tokens_total`) та розрахунковою вартістю в USD, із можливістю перегляду таблиці логів у консолі (`--logs`).

## 🏗 Архітектура та мультимодельний стек

| Компонент | Опис |
|---|---|
| **Модель 1 (Input Extractor)** | `gemini-3.5-flash-lite` — швидкий парсинг Telegram-повідомлення у Pydantic-модель `BuildingRoomInput`. |
| **Модель 2 (Primary ReAct & Tools)** | `openai/gpt-4o-mini` — оркестрація ReAct-циклу, викликів `search_fire_code_web`, `send_telegram_report` та `log_inspection_result`. |
| **Модель 3 (Analytical Output)** | `deepseek-v4-flash-0731` — зіставлення фактичних параметрів із числовими та логічними вимогами ДБН В.1.1-7:2016 і формування `FireSafetyReportOutput`. |
| **Пам'ять** | У межах запуску: стан ReAct-циклу та знайдені норми. Між запусками: таблиця `inspection_logs` у SQLite (`building_project.db`). |
| **Обмеження зупинки** | Максимум ітерацій: `10` кроків на запит; максимальний бюджет: `$0.05` на перевірку. |

## 📏 Норми ДБН В.1.1-7:2016, які перевіряє агент

1. **Гранична відстань евакуації:**
   - **п. 7.2.4:** для приміщень категорій **А** та **Б** — не більше **15 м**.
   - **п. 7.2.5:** для приміщень категорії **В** (або громадських/офісних приміщень без вказаної категорії) — не більше **25 м**.
   - **п. 7.2.6:** для приміщень категорій **Г** та **Д** — не більше **50 м**.
2. **Кількість людей у приміщенні та питома площа евакуації (п. 7.2.1):**
   - Мінімальна питома площа на 1 людину — не менше **1,5 м²/особу** (`area_sqm / occupancy >= 1.5`).
3. **Кількість евакуаційних виходів (п. 7.2.2):**
   - Не менше **2 евакуаційних виходів**, якщо в приміщенні одночасно перебуває **понад 50 осіб**, або площа приміщення категорії А/Б перевищує **100 м²**, або категорії В — **300 м²**.
4. **Габарити евакуаційних дверей у світлі (п. 7.2.8):**
   - Висота дверей — не менше **2,0 м**.
   - Ширина дверей — не менше **0,8 м** (а для приміщень з кількістю людей **понад 50 осіб** — не менше **1,2 м**).
5. **Напрямок відчинення дверей (п. 7.2.10):**
   - Двері з приміщень категорій А, Б, В або з одночасним перебуванням **понад 15 осіб** повинні відчинятися **назовні** (у напрямку виходу з будівлі).
6. **Висота приміщення та шляхів евакуації у світлі (п. 7.3.1):**
   - Не менше **2,0 м**.
7. **Група горючості оздоблення стін (п. 7.3.3):**
   - На шляхах евакуації та у приміщеннях категорій А, Б, В дозволено оздоблення матеріалами групи горючості не гірше ніж **Г1** (при `Г2`, `Г3`, `Г4` фіксується порушення).

## ⚙️ Встановлення та налаштування

### 1. Клонування репозиторію та створення віртуального середовища
```powershell
git clone https://github.com/Gariknik/FireCodeCheckerAgent.git
cd FireCodeCheckerAgent
python -m venv .venv
.\.venv\Scripts\Activate.ps1
```

### 2. Встановлення залежностей
```powershell
pip install -r requirements.txt
```

### 3. Конфігурація `.env`
Скопіюйте файл `.env.example` у `.env` та вкажіть ваші ключі:
```env
TELEGRAM_BOT_TOKEN=YOUR_BOT_TOKEN
OPENROUTER_API_KEY=YOUR_OPENROUTER_KEY
GEMINI_API_KEY=YOUR_GEMINI_KEY
DATABASE_PATH=building_project.db
```

## 🚀 Використання та команди CLI

### 1. Запуск Telegram-бота
```powershell
.\.venv\Scripts\python.exe main.py --bot
```
Під час роботи бота в консоль сервера в реальному часі виводиться **виключно ReAct Trace** кожного запиту користувача.  
Доступні команди в чаті Telegram:
- `/start` — привітання та шаблон опису приміщення
- `/logs` — перегляд останніх 5 записів перевірок у чаті та вивід таблиці в консоль

### 2. Перевірка одиничного запиту з термінала (вивід тільки ReAct Trace)
```powershell
.\.venv\Scripts\python.exe main.py --query "Перевірити приміщення: Конференц-зал, площа 70 кв.м, кількість людей в приміщенні — 60 осіб, 1 вихід, двері 0.9х2.0м, всередину, відстань до виходу — 20м."
```

### 3. Отримання логів та статистики з бази даних SQLite у консоль
```powershell
# Вивести таблицю останніх 15 перевірок та загальну статистику токенів і витрат
.\.venv\Scripts\python.exe main.py --logs

# Вивести останні 5 записів
.\.venv\Scripts\python.exe main.py --logs --limit 5

# Відфільтрувати лише перевірки з порушеннями (FAILED) або успішні (PASSED)
.\.venv\Scripts\python.exe main.py --logs --status FAILED

# Відфільтрувати логи за конкретним Telegram chat_id
.\.venv\Scripts\python.exe main.py --logs --chat-id 484076222

# Вивести логи та статистику у форматі JSON
.\.venv\Scripts\python.exe main.py --logs --json
```

### 4. Запуск усіх 6 демонстраційних сценаріїв
```powershell
.\.venv\Scripts\python.exe main.py
```

## 🧪 Тестування

Проєкт покритий автоматизованими unit-тестами (`tests/test_agent.py`), які перевіряють:
1. Валідацію Pydantic-моделей `BuildingRoomInput` (включно з необов'язковою категорією та нормалізацією літер) і `FireSafetyReportOutput`.
2. Форматування шаблонів Telegram (`🟢 PASSED` та `🔴 FAILED`) та екранування символів `\_` у URL.
3. Парсинг різних мовних конструкцій опису приміщення (`extract_room_input`).
4. Пошук у білому списку джерел (`search_fire_code_web`) та ReAct-перефразування при порожній відповіді.
5. Перевірку всіх нормативних обмежень ДБН В.1.1-7:2016 (`п. 7.2.1`, `7.2.2`, `7.2.4`, `7.2.5`, `7.2.6`, `7.2.8`, `7.2.10`, `7.3.1`, `7.3.3`).
6. Роботу з БД SQLite (`inspection_logs`), фільтрацію, статистику та табличне форматування для консолі.
7. Наскрізне виконання циклу `run_react_inspection` для сценаріїв `PASSED`, `FAILED` та `ValidationError`.

Запуск тестів:
```powershell
.\.venv\Scripts\python.exe -m unittest discover -s tests -v
```
